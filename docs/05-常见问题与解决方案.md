# 05 · 常见问题与解决方案

按类别整理本项目开发过程中遇到的所有问题与解决方案，供排查参考。

## 5.1 环境 / LeRobot API

| 现象 | 原因 | 解决方案 |
|---|---|---|
| `conda: command not found` | conda 未初始化 | `source .../conda/etc/profile.d/conda.sh` |
| `python: command not found` | 没激活环境 | `conda activate lerobot` |
| `module 'cv2' has no attribute 'aruco'` | 装的普通 opencv-python | 改装 `opencv-contrib-python` |
| `cv2` 没有 `calibrateHandEye` | OpenCV 5.x 移除了该函数 | 降到 `opencv-contrib-python==4.13.0.92` |
| `import cv2.aruco` 有但检测不到板 | CharucoDetector 对真实照片过严 | 用 `ArucoDetector` + marker 方案（已封装） |
| `no attribute 'getConnectionId'` | 新版 pybullet | `getConnectionInfo()["isConnected"]` |
| `--robot.type: invalid choice` | 机器人类型未注册 | `import lerobot.robots.so_follower`（已封装） |
| `RobotConfig.from_cli()` 不存在 | main 分支 API | 用 `@parser.wrap()` + `make_robot_from_config` |
| `robot.absolute_move` 不存在 | main 分支 API | `robot.send_action({电机名.pos: 值})` |
| `Rotation object has no attribute 'slerp'` | 新版 scipy 移除了 slerp | 用项目里的 `_quat_slerp`（手动四元数插值） |
| `EOFError: EOF when reading a line` | 用 heredoc 跑需要输入的脚本 | 存成 `.py` 文件再 `python 文件.py` |
| 目录里多出 `sedXXXXXX` 文件 | `sed -i` 临时文件残留 | 直接 `rm` 删除，无害 |

## 5.2 标定

| 现象 | 原因 | 解决方案 |
|---|---|---|
| `T_cam2ee` 平移量 > 1 米（离谱） | 标定板 `squareLength` 和打印不一致 | 量实际格子边长，改 `squareLength` 重标 |
| 手眼 ① 板位姿离散度几十 cm | 板子尺寸错 / fk 用错 link / 摄像头装在夹爪活动件上 | 检查板尺寸、确认 `fk()` 用 `st[4]`、确认摄像头刚性安装 |
| 手眼 ② 重投影误差几百像素 | 验证代码把"板坐标系"当"基座坐标系"投影（老 bug） | 用 `T_board2base = T_ee2base @ T_cam2ee @ T_board2cam` 正确链路 |
| 摄像头画面颠倒 | 摄像头装反了 | `test_camera.py` 测 FLIP，所有脚本统一 |
| 采集了 60 个姿态但后面只有 13 个能用 | 部分照片没拍好/被夹爪挡 | 重新采集，姿态变化大一点 |
| 连接时反复进校准 | `--robot.id` 没对上 | 用和之前一样的 `--robot.id` |

## 5.3 运动学 / IK

| 现象 | 原因 | 解决方案 |
|---|---|---|
| `目标位姿不可达（IK 无解）` | 5 自由度臂同时要求位置+朝向很难 | IK 改成**位置-only**（已封装） |
| 机械臂往"天花板"甩 | 随机重启 IK 解到"朝天"分支 | 随机扰动限制在当前姿态 ±20° 内，优先选靠近当前姿态的解 |
| 机械臂动作路径怪异/乱甩 | 关节空间插值跨过大姿态 | 起点先摆成合理姿势；回位用 `cartesian_move` 高位移 |
| 目标明明够得到却说无解 | `fk()` 读的是质心位置 `st[0]` | 改读 `st[4]`（link 坐标系原点） |
| 目标超出工作空间 | 框/物块太远（>0.35m） | 把框放近；程序会提示"框太远" |

## 5.4 抓取 / 放置行为

| 现象 | 原因 | 解决方案 |
|---|---|---|
| 抓取"太前/太后"、近远不一致 | 夹爪倾斜随距离变化 | 用两点校准的 x 偏移（`OFFSET_NEAR/FAR`） |
| 偏左/偏右、左右不一致 | 倾斜随左右位置变化 | 用 `Y_OFFSET_SLOPE`（一个斜率管两边） |
| 夹爪没到物块就夹紧 | 预抓高度太低 + 电机没到位 | `PRE_LIFT` 调大（0.05~0.08） |
| 夹爪插进桌面 / 一直往下戳 | `TOOL_OFFSET` 太小 | 量准"腕部到夹爪中心"，调大 `TOOL_OFFSET` |
| 夹爪夹到方块上半部 | 抓取高度偏高 | 加 `GRASP_LOW` 往下调 |
| 抓住后又松开 / 搬运时掉块 | 夹爪 20 是"刚好贴住"，不够紧 | `GRIPPER_CLOSE` 再减小 5~10 |
| 放物块时夹爪又"抓紧" | 张开后没更新 q，下一步又发回闭合值 | 张开后用 `q = wait_settled(...)` 更新（已修复） |
| 放框偏前 / 撞到框边 | 下降路径往前甩 + 框位置偏 | 下降改 `cartesian_move` 垂直下降；`BOX_OFFSET` 拉回 |
| 放框位置每次不一样 | 初始没拍到完整框 | 抬升后重新检测框（已实现）；或把框放近放正 |
| 抬升后重新检测框不准 | 倾斜视角下框中心有偏差 | 加了防呆：不可达/偏差大就用最初位置 |
| 平移到框上方时一路往下移 | 预放点比抬升位置低 | 加"保持抬升高度的平移中转点"（已修复） |

## 5.5 硬件 / 物理

| 现象 | 原因 | 解决方案 |
|---|---|---|
| 电机"卡顿"、跟不上指令 | 供电不足 / 速度太快 | 检查供电（≥5A）；`STEP_DUR` 调大、`steps` 调大 |
| 机械臂抬起来又掉下去 | 舵机力矩不足 / 堵转保护 | 检查供电、别让关节顶到限位继续按 |
| 运行完机械臂直接砸下来 | 断电时扭矩消失 | 结束先回起始姿态再断电（已实现） |
| 夹爪 0 和 100 哪个是开 | 每台标定可能不同 | `gripper_test.py` 实测；本项目 0=闭合、100=张开 |

## 5.6 运行日志（debug/）

每次运行会把「带标注的图像 + JSON（3D 坐标）」存到 `debug/`，排查"偏多少、往哪偏"直接看：

```bash
ls debug/
```
