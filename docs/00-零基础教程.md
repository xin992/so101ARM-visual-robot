# 零基础手把手教程（从零到"抓取放置"）

> 这是**跟着做**的零基础入门教程；技术细节、全部参数、完整排错表见 `docs/01~06`。

> 适用：Ubuntu 22.04 虚拟机 / Python 3.12 / LeRobot（main 分支）/ SO-101 从臂 / 单目摄像头（装在从臂上）
> 配套文件：本仓库里的全部脚本（直接能用）
> 技术原理看不懂没关系，照着复制粘贴就行。报错了先看《05-常见问题与解决方案》，解决不了就在本仓库提 Issue。

---

> ⚠️ **重要：你的 lerobot 是 main 分支（不是正式版 0.6.1）**
> 你的 `lerobot.__version__` 虽然显示 0.6.1，但实际是 GitHub `huggingface/lerobot` **main 分支的新代码**，API 和正式版 0.6.1 不一样。本教程已按 main 分支写，几个关键点：
> - 创建机械臂用 `make_robot_from_config` + `@parser.wrap()`（`robot_lib.py` 已写好，直接用）
> - 读关节用 `robot.get_observation()`，键是 `电机名.pos`；动臂用 `robot.send_action({电机名.pos: 值})`
> - 运行本教程脚本时**不要带** `--robot.cameras=...`（画面由 OpenCV 单独拿，避免和机器人抢同一个摄像头）
> - 连接时如果弹出交互式校准，说明没找到这台 id 的校准文件：带 `--robot.id=so101_follower` 可匹配你以前遥操作时校准的文件
> - 想确认代码版本/提交：`cd ~/robot_learning/lerobot && git log -1 --oneline`

## 一、这套教程是干嘛的

让你实现：**不管方块什么颜色、不管环境怎么变、机械臂底座动了也行**，机械臂都能自己"看到方块 → 抓起来 → 放进框里"。

路线：摄像头拍照 → YOLO 识别方块和框 → 用标定好的数学把像素位置换算成三维坐标 → 用 IK 算出机械臂关节角度 → 慢速走过去抓。

整套流程分 7 步，顺序别乱：

```
第 0 步  环境准备（一次性）
第 1 步  做标定板（打印一张纸）
第 2 步  相机内参标定（约 30 分钟）
第 3 步  手眼标定（最难，约 1~2 小时）
第 4 步  桌面平面标定（10 分钟）
第 5 步  YOLO 数据 + 训练（Ubuntu 拍图，Windows 训练，约 1~2 天）
第 6 步  主程序：抓取放置（先 DRY 再真机）
第 7 步  仿真（可选，建议做）
```

---

- Ubuntu 虚拟机（你已有）
- A4 纸 1 张 + 打印机 + 硬纸板 + 胶带/双面胶
- 尺子（量标定板格子和方块高度）

## 第 0 步：环境准备（一次性，约 1 小时）

看到命令行前面出现 `(lerobot)` 就对了。

> ❌ `conda: command not found`
> 说明 conda 没被找到，用上面第一行 `source ...` 引入；如果路径不对，用 `find /home/x/robot_learning -name "conda.sh"` 找一下，把真实路径替换进去。

### 0.2 建工作文件夹 + 把脚本放进去

```bash
mkdir -p ~/robot_learning/pick_place
cd ~/robot_learning/pick_place
```

把整个仓库克隆/拷贝到这个文件夹：

- **方式 A（推荐，git clone）**：
```bash
git clone https://github.com/xin992/so101ARM-visual-robot.git ~/robot_learning/pick_place
```
- **方式 B（手动拷贝）**：从 Windows 把整个项目文件夹拷到 Ubuntu 的 `~/robot_learning/pick_place/`（可跳过 `datasets/`、`debug/` 等大目录）。

复制完后，在 Ubuntu 里确认：

```bash
ls ~/robot_learning/pick_place/*.py
```

应该能看到 robot_lib.py、step1_charuco.py 等脚本。

### 0.3 修 OpenCV（关键！aruco 是 contrib 模块）

常见报错 `module 'cv2' has no attribute 'aruco'`，是因为装的 opencv 不带 contrib。执行（**务必装 4.13，不要装 5.x**，5.x 没有手眼标定函数 `calibrateHandEye`）：

```bash
pip uninstall -y opencv-python opencv-python-headless opencv-contrib-python opencv-contrib-python-headless
pip install opencv-contrib-python==4.13.0.92
python -c "import cv2; print(cv2.__version__); import cv2.aruco; print('aruco ok')"
```

看到 `aruco ok` 就对了。

> ❌ `pip` 太慢 / 超时：加国内镜像：
> ```bash
> pip install -i https://pypi.tuna.tsinghua.edu.cn/simple opencv-contrib-python
> ```

### 0.4 装 3 个包

```bash
pip install ultralytics scipy pybullet
```

> 说明：你的 Python 3.12 环境不要装 `lerobot[kinematics]`（placo 在 3.12 很难装），我们的运动学直接用 pybullet，已经在脚本里写好了。

### 0.5 找到 SO-101 的 URDF 路径并填进 robot_lib.py

URDF 是机械臂的 3D 模型文件，算运动学要用。执行：

```bash
cd ~/robot_learning/pick_place
python -c "from robot_lib import find_urdf; find_urdf()"
```

会打印出一串 `.urdf` 路径，找里面带 `so101` 的那一个，然后打开 robot_lib.py 修改。

**如果什么都没打印**：说明你的 lerobot 是浅克隆，源码里没有 URDF 文件。**不用下载了**——仓库里的 `urdf_so101/` 文件夹已经有官方校准过的 URDF 和全部 3D 模型：
1. 把整个 `urdf_so101` 文件夹拷到 Ubuntu 的 `~/robot_learning/pick_place/` 下
2. 确认里面有 `so101_new_calib.urdf` 和 `assets/`（13 个 .stl）
3. `robot_lib.py` 里**已经填好**这个路径，不用改（除非你的路径不一样）：

```python
URDF_PATH = "/home/x/robot_learning/pick_place/urdf_so101/so101_new_calib.urdf"
```

> 说明：`so101_new_calib.urdf` 来自官方 TheRobotStudio/SO-ARM100 仓库，是**校准过**的 SO-101 模型。它的关节名（shoulder_pan / shoulder_lift / elbow_flex / wrist_flex / wrist_roll / gripper）和 lerobot 0.6.1 的电机名**完全一致**，`robot_lib.py` 已经按这个配好，运动学直接可用。如果你自己有 `so101_new_calib.urdf` 之类校准过的模型，优先用你自己的。

```bash
gedit robot_lib.py      # 或者：nano robot_lib.py
```

把文件最上面这一行改成你找到的路径：

```python
URDF_PATH = "/你找到的/so101.urdf"
```

保存退出（nano 里：`Ctrl+O` 回车保存，`Ctrl+X` 退出）。

### 0.6 自检

```bash
python -c "import cv2, numpy, scipy, pybullet, ultralytics; print('all imports ok')"
python -c "from robot_lib import PyBulletKin; k = PyBulletKin(); print('FK/IK ok')"
```

第二个命令会打印"手臂关节映射"和"末端 link 名字"，**把这两行记下来或截图**，后面要核对。

> ❌ `FileNotFoundError: 找不到 URDF 文件`
> 0.5 步的路径没填对，重填。
>
> ❌ `ModuleNotFoundError: pybullet` 等
> 0.4 步的包没装成功，重新装。
>
> ❌ 关节映射全是 0 或顺序明显不对
> 说明电机名和 URDF 对不上。把 `robot_lib.py` 里 `ARM_MOTOR_NAMES` 改成你机械臂真实的电机名（运行第 3 步 A 时会打印）。

## 第 2 步：相机内参标定（约 30 分钟）

这个步骤告诉程序"照片上的一个像素，对应相机前方什么方向"。

### 2.1 运行

```bash
cd ~/robot_learning/pick_place
python step2_intrinsics.py
```

会弹出摄像头窗口。

### 2.2 操作要点

- 把标定板拿到相机前，摆**不同姿态**：远一点、近一点、左右倾斜、上下倾斜、转个角度
- 每摆一个姿态按**空格**拍照，**至少拍 30 张**
- 每张要满足：板**完整**出现在画面里、清晰、**不要反光**（避开灯光直射）
- 拍够后按 **q**，脚本自动开始计算

### 2.3 看结果

会打印：

```
重投影误差（像素，越小越好：<0.5 很好，<1 能用）: 0.xx
```

看到 `已保存 calib/calib_intrinsics.npz` 就完成了。

> ❌ `摄像头读不到画面`：把脚本里 `CAM_INDEX = 0` 改成 1 或 2 再试；或者先拔插摄像头。
> ❌ `有效图片太少`：多数是反光/模糊/板不完整。改善光照再拍。
> ❌ 重投影误差 > 1：说明标定板没贴平（贴硬纸板）、或者 squareLength 量错了、或者照片模糊。重拍。

## 第 3 步：手眼标定（最难的一步，约 1~2 小时）

因为摄像头装在机械臂上，程序必须知道"相机相对机械臂末端"的位置关系，这个变换就是 `T_cam2ee`。

### 3.1 固定标定板

把标定板**平放在桌面上**（黑色格子朝上），用胶带固定好。**这个板子在第 4 步还要用，全程不要动它。**

### 3.2 采集（step3a）

```bash
cd ~/robot_learning/pick_place
python step3a_collect_handeye.py --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=so101_follower

```

> 如果机械臂的串口不是 `/dev/ttyACM0`，先查一下：`ls /dev/ttyACM*`，把端口改对。
>
> **如果连接时弹出校准提示**（"Move ... to the middle of its range of motion..."）：说明没找到这台 id 的校准文件。要么按屏幕提示完成一次交互式校准（机械臂会自己扫关节，几分钟），要么确认 `--robot.id` 和你以前遥操作校准时的 id 一致（校准文件是按 id 存的）。校准完成后会自动保存，以后连接直接用。

窗口打开后，**用键盘控制机械臂**（脚本会自动连接机械臂并读取角度）：

| 按键 | 作用 |
|---|---|
| `q` / `w` | 关节 1 正转 / 反转（每次 5 度） |
| `e` / `r` | 关节 2 正转 / 反转 |
| `t` / `y` | 关节 3 正转 / 反转 |
| `u` / `i` | 关节 4 正转 / 反转 |
| `o` / `p` | 关节 5 正转 / 反转 |
| `g` | 夹爪开 / 关 |
| `空格` | 保存当前姿态（图像 + 关节角） |
| `x` | 结束 |

**要点**：
1. 先按 `g` 让夹爪张开，避免挡到标定板
2. 用按键把机械臂摆到"相机能看到桌面上的标定板"的姿态（画面里板要完整、清晰）
3. 每摆好一个姿态按**空格**保存；**共保存 15~20 个**
4. 姿态之间**变化要大**：相机离板近一点、远一点、高一点、低一点、侧一点都要有
5. 脚本顶部会打印 `机械臂电机： [...]`，**和 robot_lib.py 里 ARM_MOTOR_NAMES 对比一下，不一样就改**

> ❌ 机械臂不动 / 报端口错：检查串口、机械臂供电、USB 线。先跑通 `lerobot-teleoperate` 能控制臂，再回来。
> ❌ 按空格后说检测不到板（第 3 步 B 会提示）：姿态没摆好，板没在画面里或太斜/反光，重新采集。
> ❌ 某个关节按键没反应：可能那个关节已经到限位，换方向按；或电机卡住（用手轻轻扶一下，但别硬掰）。

### 3.3 计算（step3b）

```bash
python step3b_calib_handeye.py
```

会打印 `T_cam2ee`，然后自动验证：

```
重投影误差：平均 x.x 像素 ...
合格：平均误差 < 10 像素，可以继续下一步。
```

看到 `已保存 calib/calib_handeye.npz` + "合格"就完成了。

> ❌ `有效姿态太少（<10）`：回去 step3a 多采几个、姿态更丰富。
> ❌ `误差偏大`：标定板没贴平、照片糊、姿态太单一。重采重算。
> ❌ 报 `cv2.Rodrigues` / `solvePnP` 之类的错：对照附录 B，解决不了提 Issue。

## 第 4 步：桌面平面标定（10 分钟）

因为相机是单目没有深度，我们假设"方块和框都放在桌面上"，用"像素射线 与 桌面平面 求交点"来算 3D 坐标。所以要知道桌面在哪。

**好消息：你第 3 步把标定板平放在桌面上采集的，板面就是桌面。这一步直接用那些数据，不用再采集。**

```bash
cd ~/robot_learning/pick_place
python step4_calib_table.py
```

看到：

```
桌面平面：法向量 n = [0.00 0.00 1.00]（大致是这个，z 接近 1 就对了）
已保存 calib/table_plane.npz
```

就完成了。

> ❌ n 的 z 是负数（-1 左右）：说明板法线朝下，取反即可。把 `step4_calib_table.py` 里 `n_ = T_board2base[:3, 2]` 改成 `n_ = -T_board2base[:3, 2]` 再跑。不过通常平放时 z 就是正的。

## 第 5 步：YOLO 数据 + 训练（约 1~2 天，大部分是等训练）

### 5.1 Ubuntu 上采集数据

```bash
cd ~/robot_learning/pick_place
python step5_collect_yolo.py
```

窗口里**空格保存、q 退出**。拍摄时务必变化多样（这决定 YOLO 的泛化能力）：

- 方块换**多种颜色、多种大小**
- 方块和框放**不同位置、不同距离**
- **不同光照**：开灯/关灯/拉窗帘
- 桌面上放点杂物（干扰物）
- 相机（机械臂）换不同高度和角度

**目标 300~600 张**，拍完在 `datasets/raw/` 里。

### 5.2 把数据拷到 Windows

把整个 `datasets/raw` 文件夹拷到 Windows（共享文件夹或 scp），准备标注。

### 5.3 Windows 上标注（labelImg）

```powershell
pip install ultralytics labelImg
labelImg
```

操作：
1. 左侧 `Open Dir` 选 `raw` 图片文件夹
2. `Change Save Dir` 选一个空的 `labels` 文件夹
3. 右上角把 `PascalVOC` 点成 **`YOLO`**
4. 用鼠标画框：红方块标 `red_fang`，棕方块标 `brown_fang`，目标框标 `bule_box`（第一次会弹窗让你输入类名）
5. 每张画完 `Ctrl+S` 保存，`D` 下一张

> 注意：类名必须和 `step7_pick_place.py` 的 `CUBE_CLASSES` / `BOX_CLASSES` 一致。画面里没有就不标。

### 5.4 整理数据集 + Windows 训练

建一个文件夹 `cube_box`，里面这样放：

```
cube_box/
├── images/
│   ├── train/   (约 80% 的图)
│   └── val/     (约 20% 的图)
├── labels/
│   ├── train/
│   └── val/
└── dataset.yaml
```

（图片和对应的 .txt 标注要同名、同属 train/val。可以手动拖，或用脚本按 8:2 随机分。）

`dataset.yaml` 内容（路径改成你的实际路径）：

```yaml
path: C:/Users/你的用户名/Desktop/cube_box
train: images/train
val: images/val
names:
  0: red_fang
  1: bule_box
  2: brown_fang
```

训练（Windows PowerShell，有 NVIDIA 显卡会快很多）：

```powershell
cd cube_box
yolo segment train data=dataset.yaml model=yolo26n-seg.pt epochs=200 imgsz=640 batch=16 device=0
```

- 没显卡：去掉 `device=0`（会很慢，先用 `epochs=50 imgsz=480` 试跑通）
- 显存不够报 `CUDA out of memory`：`batch=8` 或更小

训练结束后在 `runs/segment/train/weights/` 找到 **`best.pt`**。

### 5.5 把 best.pt 拷回 Ubuntu

```bash
# Ubuntu 里先建文件夹
mkdir -p ~/robot_learning/pick_place/weights
```

然后把 `best.pt` 拷到 `~/robot_learning/pick_place/weights/best.pt`（共享文件夹或 scp）。

### 5.6 预览检测效果

```bash
cd ~/robot_learning/pick_place
python step6_detect_preview.py
```

窗口里能看到 red_fang / brown_fang / bule_box 的绿色框就成功了。

> ❌ 检测不到 / 框乱跳：数据太少或变化不够；把 `step6_detect_preview.py` 里 `conf=0.3` 调低到 `0.2`；或者回去多采数据重训。
> ❌ 把干扰物也框成 cube：数据里多放些干扰物并标对。

## 第 6 步：主程序：抓取放置

### 6.1 先跑 DRY 模式（只检测，不动机械臂！）

```bash
cd ~/robot_learning/pick_place
python step7_pick_place.py --dry
```

会打印方块和框的 3D 坐标。**拿尺子量一下方块真实位置，和打印的坐标对比**：

- 如果数量级对、误差在几厘米内 → 标定基本正确，可以上真机
- 如果差很远 → 回第 2~4 步检查标定

> ❌ `没有同时检测到方块和框`：先用 step6 看检测，调整位置/光照/角度再跑。

### 6.2 真机运行（人必须在旁边守着！）

先把机械臂摆到一个安全的中间姿态，然后：

```bash
python step7_pick_place.py --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=so101_follower
```

脚本会：检测 → 移到方块上方 → 再拍一张修正 → 下抓 → 抬升 → 移到框上方 → 下放 → 松开 → 抬升。

**安全建议**：
- 第一次跑把 `step7_pick_place.py` 顶部的 `STEP_DUR = 0.2` 改成 `0.4`（更慢更稳）
- 手里一直放在机械臂电源旁边，不对劲立刻断电
- 每次跑完看 `debug/` 文件夹里的图片和 json（自动记录，方便排错）

### 6.3 常见问题

> ❌ `IK 无解`：目标点超出机械臂能到达的范围。把 `PRE_LIFT` 调大一点，或调整方块/框的位置，或把抓取 yaw 换 90° 试试。
> ❌ 抓偏了：看 `debug/000_detect.jpg` 框有没有框对；框对了还偏，多半是标定误差，回第 2~4 步；也可以把 `STEP_DUR` 调大减少电机抖动。
> ❌ 高度不对（没碰到方块就夹/撞桌）：检查 `CUBE_H`（方块高度）、第 4 步桌面平面是否准。
> ❌ 夹爪角度不对：`GRIPPER_CLOSE` / `GRIPPER_OPEN` 改成你机械臂实际的张开/闭合角度（先单独测：夹爪张开时角度是多少、闭合时是多少）。
> ❌ 电机卡顿抖动：`STEP_DUR` 调大；检查供电（换大电流电源/USB 口）；每小步之间有 `wait_settled` 等待到位，别急。

## 附录 B：通用排错总表（按报错关键字查）

| 报错 / 现象 | 原因 | 解决办法 |
|---|---|---|
| `conda: command not found` | conda 没在 PATH | 先 `source /home/x/robot_learning/conda/etc/profile.d/conda.sh` |
| `no attribute 'aruco'` | opencv 不带 contrib | 第 0.3 步，改装 `opencv-contrib-python` |
| `ModuleNotFoundError: ultralytics/scipy/pybullet` | 包没装 | 第 0.4 步 |
| `FileNotFoundError: 找不到 URDF` | URDF_PATH 没填对 | 第 0.5 步 |
| find_urdf() 什么都没打印 | 浅克隆缺 URDF | 直接用教程配套的 urdf_so101 文件夹（见第 0.5 步） |
| `摄像头读不到画面` | 摄像头编号不对/没连好 | 改 `CAM_INDEX`；拔插摄像头 |
| `有效图片太少 / 检测不到标定板` | 反光/模糊/板不全/边长错 | 改善光照、贴平板、量准 squareLength |
| 重投影误差 > 1 | 板没贴平/边长错/糊 | 重拍，贴硬纸板 |
| 手眼重投影误差 > 10 像素 | 姿态太单一/板没贴平 | 重采 15~20 个差异大的姿态 |
| 机械臂不动 / 端口报错 | 串口不对/供电不足 | `ls /dev/ttyACM*` 核对端口；检查供电 |
| 电机"咔咔"卡顿 | 供电不足/速度过快 | `STEP_DUR` 调大；换供电；分步等待 |
| `IK 无解` | 目标超出工作空间 | 调 `PRE_LIFT`、换位置、yaw 换 90° |
| 抓偏/高度不对 | 标定误差/参数错 | 看 debug 图；检查 CUBE_H、桌面平面、STEP_DUR |
| `CUDA out of memory`（Windows 训练） | 显卡显存不够 | `batch=8` 或更小 |
| 检测不到 cube/box | 数据少/conf 高 | 调 `conf=0.2`；多采数据重训 |
